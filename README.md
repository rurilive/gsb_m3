# leasekv

纯标准库的内存 KV，无外部依赖。应用里常要几个进程或线程按 key 抢着改同一份数据，
leasekv 就是管这层按键存取的 KV。

## 现状

leasekv/kv.py 提供一张无租约的字典 KV LeaseKV：

- put(key, value)：写入或覆盖一条，同名主键覆盖时位置不变，值按值拷贝存下
- get(key, default=None)：按键取回值的一份拷贝，键不存在返回 default，并记一次命中或未命中
- delete(key)：按键删除，删到返回 True，本来就不在返回 False
- keys：按写入顺序给出全部主键；contains：判断键是否存在
- stats：live / hits / misses 计数快照

现有实现只有平铺字典这一条路：写进去的条目一直留着，谁能写全靠调用方自己守规矩，
跑飞了或者忘了收尾的调用方回来照样能覆盖别人的改；没有租期也没有时钟，租约过没过
没法在测试里稳定复现；没有后台回收，也没有在抢占用同一个 key 时递增的 token；key
变更之后没人被告知；并发下同一 key 谁在持有也不清楚。

## 问题

把现有这套朴素 KV 扩成生产可用的按键租约 KV，缺的东西集中在几处：没有按 key 绑定
的持有者与租期，谁都能改任意 key；没有注入时钟，租约到期与否无法稳定复现；没有续约
入口，持有者没法在租期内延长租期；没有看门狗批量回收过期租约，过期项只能靠人手清；
抢占后没有递增的 token 兜底，旧持有者带旧 token 回来照样能写；key 变更没有通知，
订阅者不知道数据已换手；并发 grant 与续约下同一个 key 可能被两个持有者同时认领；
非正 ttl 没被立刻拒绝，重复 grant 的语义也不明确。
