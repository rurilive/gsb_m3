# kmpmatch

纯标准库的字符串匹配工具雏形，无外部依赖。

## 现状

kmpmatch/naive.py 提供这几条朴素能力：

- occurrences、count：模式在文本里出现的全部起点（升序、允许重叠）与次数，对每个起点逐位对齐比较
- occurrences_many：多模式匹配，逐个模式各自扫一遍文本
- prefix_naive：最长公共前后缀长度数组，对每个候选长度重新逐位比较
- min_period、is_periodic：最小整周期长度与是否存在真周期，靠逐位试
- TextTools：绑定一段文本，方法同上并累计逐字符比较计数，可读取与清零

所有结果都对，但失配之后前面比出来的信息没被复用，每个起点都要重新
比较一遍，没有以失配函数为基础的线性匹配，也没有独立的交叉核对口径。

## 问题

文本与模式一长，逐位比较的次数就随两者长度乘积上涨；同一段已经比过
的对齐在同一趟里被反复重扫，代价浪费在重复劳动上；想拿另一条独立口径
互相印证，也缺现成的入口。

## 目标

在当前基础上补出以失配函数为基础的线性匹配主路径、由同一失配函数导出
的最短周期与循环节判定、独立的交叉核对口径与多模式自动机口径，见任务
描述。约束：

- 现有行为与 tests/test_naive.py 基线保持一致（基线一个字不改）
- 纯标准库
- 新老两条路径对同一批数据事实逐项一致

## 运行

```bash
python3 demo.py
python3 -m unittest discover -s tests -v
```
