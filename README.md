# autocmplt

纯标准库的内存前缀自动补全雏形，无外部依赖。

## 现状

autocmplt/scan.py 提供一个 Autocomplete：

- add、remove：按词加入或删除，重复加入叠加热度，词不存在报 KeyError
- learn：记录一次选用，把该词热度加一
- words、count_of：按加入顺序取回词表、按词取回热度
- candidates：唯一的补全入口，把每个词拿出来用 startswith 判前缀，
  命中的词按热度降序、同热度按字典序升序返回
- scans：上一次 candidates 扫过的词数，用来观察扫描代价

补全只有全量扫描这一条路，每个词都要看一遍，候选多时排序也全靠整表
重排；没有字典树，没有按前缀收窄的检索，没有取前 K 的截断，没有模糊
匹配，热度也只能靠手工传 count，选过一次不会自己涨。

## 问题

每取一次候选都要把整张词表从头扫到尾，词表一大就白扫；命中之后还要把
所有命中词排序，哪怕调用方只想要前几个；前缀路径上没有任何聚合，想知
道某个前缀下有多少词、最热的词是谁，只能全枚举一遍再数；热度是静态的，
用户选了一次推荐的词，热度不会跟着变，久用之后排序还是老样子；删词只
把词本身拿走，前缀的规模与热度得靠重新扫描才知道；打错一个字符就一个
候选也补不出来；整张词表也没有办法存下来再读回去。

## 目标

在当前基础上补出字典树检索、热度排序、Top-K 截断、增量学习、模糊补全
与序列化，见任务描述。约束：

- 现有行为与 tests/test_scan.py 基线保持一致（基线一个字不改）
- 纯标准库
- 前缀候选与热度排序必须与朴素全量扫描逐词对拍一致，字典树只该省下
  扫描量，不该改结果
