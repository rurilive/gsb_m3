# txnkit

进程内键值存储与事务，纯标准库，单线程模型，无外部依赖。

## 现状

`txnkit/store.py` 提供两个入口：

- `KVStore(initial=None)`：`set(key, value)` / `get(key, default=None)` /
  `delete(key)`（返回是否删掉）/ `keys()`；`begin()` 开启一个事务
- `Transaction`：`get` / `set` / `delete`，`commit()` 提交，`rollback()` 回滚；
  事务关闭后再调用会抛 `RuntimeError`
- `ConflictError`：提交时发现键在事务开始后被其他事务改过时抛出，约定见任务描述
- 事务开始时给主表拍一份快照，事务内的读走快照，写入先记在写集合里，
  提交时并回主表；每个键带一个版本号，本来是为提交时的冲突检测准备的

## 问题

联调环境里事务的隔离性对不上：事务内写进去的值自己读不到；提交后外面改动
传进去的那个对象会影响存储；回滚之后被删掉的键没回来；两个事务先后提交时，
先提交的结果会被后一个冲掉。

## 目标

见任务描述。约束：

- 现有方法行为与 `tests/test_store.py` 基线保持不变（基线一个字不改）
- 纯标准库
- `python3 demo.py` 能直接跑通

## 运行

```bash
python3 demo.py                          # 五个隔离场景演示
python3 -m unittest discover -s tests -v # 行为基线测试
```

## 修复记录

`txnkit/store.py` 重写了事务的读、写、提交、回滚路径，四处隔离漏洞都堵上了：

- **读自己的写**：`Transaction.get` 现在按「事务内删除 → 事务内写入 → 开始时快照
  → default」的顺序读，`set` 完立刻 `get` 拿到的就是新值；事务期间其他事务的
  提交不会穿透进来（快照隔离）。
- **值的所有权**：初始化、`set`、`get`、`snapshot` 以及事务提交的所有边界都改用
  `copy.deepcopy`，存储与调用方互不共享嵌套 dict/list，调用方事后再改自己手里的
  对象不影响已落地的数据。
- **回滚干净**：`set`/`delete` 只改事务内的暂存区，主表在提交前完全不动；
  `rollback` 只是丢弃暂存区，被删、被改的键自然保持事务开始时的值。
- **逐键合并提交**：`commit` 不再整表替换，只把本事务写过/删过的键并回主表，
  两个事务各写各的键可以先后落地，互不顶掉。
- **冲突检测**：`begin()` 时记下各键版本号；提交时凡是本事务碰过（写或删）的键，
  只要主表当前版本与开始时不一致，就判冲突——抛 `ConflictError`（消息内冲突键按
  字典序列出），本次提交整体作废、主表原样不动，事务仍可 `rollback` 收尾；
  只读事务不判冲突。

新增 `tests/test_isolation.py` 钉住上述行为（24 个用例），基线文件
`tests/test_store.py` 未做任何改动。
