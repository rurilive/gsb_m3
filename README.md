# chainkit

一个纯标准库的矩阵连乘工具箱，无外部依赖。编译器后端的算子融合、报表里的
批量矩阵乘、图算法里的权重路径，最后都要给一串矩阵相乘挑一个括号化，让标量
乘法次数尽量少，chainkit 就是干这件事的那一层。

## 现状

- `chainkit/chain.py`：链用一维整数序列 `dims` 表示，`len(dims)` 减一就是
  矩阵个数；`check_dims` 校验维度都为正整数，越界或非法一律抛 `ChainError`。
- `naive_cost` 与 `naive_optimal`：对区间枚举每一个分裂点，左右两半各自
  递归重算代价，取和最小者；最优括号化靠同一套枚举回代拼出嵌套二元组。
- `naive_count`：数最优括号化方案的个数，每个分裂点处左右最优值之和等于
  区间最优值就累加左右方案数的乘积，并列的分裂点都算进去。
- `parse_plan`、`plan_to_string`、`naive_plan_cost`：在括号串与嵌套方案之间
  来回，括号串里每一层括号是一次乘法，逐段重扫取端点维度。
- `whole_cost`、`whole_optimal`、`whole_count`：整条链上的便捷入口。
- `chainkit/ChainError`：所有可诊断错误的基类，带 `message`、`position` 与
  `data`，越界、非法维度、括号串不合法都从它出发。

## 问题

现在每一层都从零重算左右子区间，同一个子问题被反复展开，链一长分裂点的枚举
量就变成立方甚至更高量级，稍长一点的链就跑不动了；最优括号化只有一套枚举，
并列最优时给出的方案依赖循环里先遇到哪个分裂点，口径没有固定下来；方案个数
也靠递归重展开，和最优值各算各的，两边的结论没有互相印证。
