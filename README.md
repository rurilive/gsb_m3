# exprx

规则引擎内嵌的表达式求值模块：词法 → 递归下降语法分析 → 求值，纯标准库。

## 语言语义

- 字面量：整数、小数；变量名：字母/下划线开头
- 运算符优先级（低 → 高）：`or` < `and` < 比较（`== != < <= > >=`）< `+ -` < `* / // %` < `^`（乘方，右结合）
- 一元负号：作用于整个乘方结果，`-2^2` 的值是 `-4`；`2^-3` 合法
- `and` / `or` 短路求值：左侧已能定值时右侧不求值，结果为布尔值
- `//` 与 `%` 是向下取整语义（与 Python 一致）：`-7 // 2 == -4`，`-7 % 2 == 1`
- `let x = e in body`：绑定仅在 body 内可见，退出后外层同名绑定不受影响，多次 evaluate 之间互不泄漏
- 除数为 0 时抛 `ZeroDivisionError`；引用未绑定变量抛 `NameError`

## 使用

```python
from exprx import Evaluator

ev = Evaluator()
ev.evaluate("let rate = 0.9 in amount * rate", {"amount": 80})
```

## 运行

```bash
python3 demo.py
```

## Known Issues

以下问题均已修复：

1. **`-2^2` 结果符号相反（算出 4，预期 -4）**
   - 根因：旧语法分析把一元负号放在原子层处理（`_atom` 见到 `-` 直接归约为 `("neg", atom)`），优先级高于乘方，于是 `-2^2` 被解析成 `(-2)^2 = 4`，与"一元负号弱于乘方"的语义不符。
   - 修复：在乘除层与乘方层之间新增独立的一元运算层 `_unary`，一元负号作用于整个乘方，乘方右支也经 `_unary` 解析（`2^-3` 仍合法）。现 `-2^2 = -(2^2) = -4`，`2^-3` 保持合法。

2. **`x != 0 and 10 / x > 2` 在 x=0 时抛 `ZeroDivisionError`**
   - 根因：求值器对 `and`/`or` 无条件先求左右两支，再用 Python 的 `and`/`or` 合并，右侧 `10 / x` 即使在左支已能定值时仍被求值，除零随即抛出。
   - 修复：改为显式短路求值——`and` 左支为假直接返回 `False`，`or` 左支为真直接返回 `True`，均不再求右支；结果仍为布尔值。

3. **`-7 % 2` 算出 -1、`-7 // 2` 符号错误**
   - 根因：旧实现用 `int(left / right)` 模拟整除，对负数向零截断（`int(-3.5) == -3`）而非向下取整，取模也由该截断值推导，导致余数符号随被除数走，不符合文档声明的地板语义（也与 Python 不一致）。
   - 修复：`//` 与 `%` 直接使用 Python 原生地板除/取模（`left // right`、`left % right`）。现 `-7 // 2 == -4`、`-7 % 2 == 1`，且整除结果保持整数类型。

4. **`let x = 99 in ...` 污染外层及后续规则的同名变量**
   - 根因：`let` 求值时直接把绑定写入求值器唯一的环境表 `_env`，body 求值结束后既不恢复旧绑定、也不删除新键，绑定在表达式结束后仍然残留，并随求值器实例跨多次 `evaluate` 泄漏。
   - 修复：进入 `let` 前保存该名字的原绑定（含"是否已绑定"状态），body 求值后在 `finally` 中恢复原绑定或删除新增键。绑定现在仅在 body 内可见，外层同名绑定与后续规则互不影响。
