# lfukit

按访问频次淘汰的缓存，纯标准库，无外部依赖。缓存满了不瞎扔，先把用得最少的
挤出去，用得多的一直留着。

## 现状

lfukit/cache.py 提供 LFUCache：

- LFUCache(capacity)：按条目数上限建缓存
- get(key)：命中返回值并把次数加一，未命中返回 None 并记一次未命中
- put(key, value)：新键在容量满时先淘汰一条，已有键改值并把次数加一
- peek(key)：只取值，不改次数、不动统计
- stats()：容量、条目数、命中、未命中与淘汰数
- keys() / len() / in：遍历键、条目数与成员判断

淘汰挑次数最小者，次数相同挑最久未使用者。

## 问题

条目一旦写入就永远留着，过期数据不会被清掉；次数只涨不落，早年的一次热点
能一直压着近期的高频键；淘汰只在 put 新键时发生，别的时候攒着不管；
也没有过期的量化出口，调参靠猜。
