# signalbox

一个纯标准库的反应式信号库，无外部依赖。配置刷新、派生视图与缓存失效这类
场景里，一个值改动之后要牵动一批下游结果，signalbox 想统一这层传播语义。

## 现状

`signalbox/observable.py` 提供 `Observable`，一个朴素可观察值：

- `Observable(value=None)`：存一个值，缺省为 `None`
- `get()`：读当前值
- `set(value)`：更新值并把 `(self, value)` 同步通知给全部订阅者，返回 `None`
- `subscribe(fn)`：注册订阅者，返回一个退订函数
- `unsubscribe(fn)`：按引用退订，未注册过返回 `False`
- `subscribers()`：订阅者列表快照，按注册顺序
- `version`：设值次数，从 0 起
- 内部一把可重入锁保护读写，订阅者抛出的异常原样冒泡

设值即通知，订阅者拿不到依赖关系，也就无从判断自己是否真的受影响；
没有派生值，没有惰性求值，更没有把一轮多次改动合并成一次通知的批处理。

## 问题

值一改就逐个通知，下游谁需要谁不需要分不清；派生值只能靠订阅回调手工重算，
每次都要重来一遍；一轮业务里连着改好几个信号，订阅者被反复打扰，中间态
还会被读到；派生之间若互相引用，出了环也没有任何提示。
