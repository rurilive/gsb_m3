# stoerwagner

纯标准库的无向图全局最小割工具雏形，无外部依赖。

## 现状

stoerwagner/naive.py 提供几条朴素能力，全靠逐对点跑最大流与枚举切分：

- pairwise_min_cut_value：对图上每一对点各从头跑一遍最大流，取所有点对里最小
  的那个流值当作全局最小割
- max_flow_value：源点与汇点之间做朴素增广，反复找一条增广路并推流
- exhaustive_min_cut_value：枚举所有非空真切分，算跨越权重取最小，小图对照用
- normalize_edges：整理无向边表，校验边编号唯一、拒绝自环与负权重
- MinCutTools：绑定一张无向图，求全局最小割并累计推流次数
- Erro：模块所有对外异常的公共基类，GraphError 与 CutError 都继承它

结果都对，但每一对点都要把最大流重算一遍，点对数是点数的平方，点一多就跑不
动，也没有最大邻接搜索扩展与收缩合并这类做法。

## 问题

点数一上去，点对数按平方上涨，每一对还要从头跑一遍最大流，重复劳动极多；想
在扩展合并做法与逐对点最大流做法之间互相印证并做规模对照，也缺入口。

## 目标

在当前基础上补出反复用最大邻接搜索扩展、合并最后两点这条路，只需点数减一次扩
展就得到全局最小割值，另起一条独立做法（逐对点最大流）在固定输入上逐项一致，
并暴露两条路各自的规模计数，见任务描述。约束：

- 现有行为与 tests/test_naive.py 基线保持一致（基线一个字不改）
- 纯标准库
- 两条路结果逐项一致，各条路不许互相调用
