# poolx

执行器工具包，纯标准库，无外部依赖。

## 现状

`poolx/pool.py` 提供 `SyncPool`：

- `submit(fn, arg)`：立刻同步执行 `fn(arg)`，结果存入结果列表，返回其下标
- `results()`：返回全部结果的拷贝，按提交先后排列
- `get(i)`：返回第 `i` 个结果
- `size()`：已提交（已执行）的任务个数
- `wait()`：空操作
- `shutdown()`：空操作

它名字里虽然有个池字，但内部没有工作线程，也没有任务队列。每次提交都在
调用线程里顺序地把任务跑完再缓存结果，从不真正并发；没有异步拿到结果的
凭据，也没有异常传递和超时。

## 问题

任务是顺序执行的，跑不快；提交必须等到函数返回才拿得到下标，无法先收下
任务再慢慢取结果；任务抛出的异常会直接从 `submit` 里冒出来，没法区分是
哪一个任务失败，更谈不上不影响其它任务；没有并发度上限的概念；关闭之后
还能继续提交，缺少快速失败的手段。
