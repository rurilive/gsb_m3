# packwire

消息总线用的二进制编解码库，纯标准库，无第三方依赖。

## 包结构

- `packwire/framing.py`：线格式的紧凑原语（首部、整数、浮点、深度上限）
- `packwire/codec.py`：`encode(obj) -> bytes` 与 `decode(data) -> obj`，
  支持 int、float、str、bytes、list、dict（字符串键），可任意嵌套；
  布尔按整数处理，解码结果都是普通 Python 值
- `packwire/stream.py`：`StreamDecoder`，按块喂入的增量解码器，
  偏移按整个流计，结果与一次性 `decode` 一致
- `packwire/errors.py`：`PackError` 是基类，`EncodeError` 报编码问题，
  `DecodeError` 报解码问题并带 `offset` 属性

错误与偏移约定：认不出的类型码、坏 UTF-8、非规范形、输入中途截断、
尾部有多余字节、嵌套过深，都报 `DecodeError`；`offset` 指向第一个出
问题的字节，输入提前耗尽时指向输入长度，也就是下一个本该出现却没有
的字节。

## 运行

```bash
python3 demo.py                          # 紧凑格式与流式解码演示
python3 -m unittest discover -s tests -v # 行为基线 + 向量对拍
```

## 线格式

CBOR 风格的规范形变长编码。每个值以一个首部字节开头：高三位是主
类型，低五位是附加信息。

附加信息：

- 0..23：参数直接内联在首部字节里
- 24 / 25 / 26 / 27：后跟 1 / 2 / 4 / 8 字节大端参数
- 28..31：保留，出现即报错

主类型：

| 主类型 | 含义 | 参数 |
| --- | --- | --- |
| 0 | 非负整数 | 值本身（0 .. 2^64-1） |
| 1 | 负整数 | -1-n（覆盖 -1 .. -2^64） |
| 2 | 字节串 | 字节长度 |
| 3 | 文本（UTF-8） | 字节长度 |
| 4 | 数组 | 元素个数 |
| 5 | 字段表 | 键值对个数，键必须是文本 |

浮点占三个固定类型码（不属于主类型）：`0xd9` 半精度（2 字节）、
`0xda` 单精度（4 字节）、`0xdb` 双精度（8 字节），大端 IEEE 754。

规范形规则（解码只认这一种）：

- 首部必须最短：能用更小的宽度就不许用更大的
- 浮点必须取能无损表示的最短宽度；NaN 固定为 `d97e00`
- 字段表的键按规范序排列：先比编码后键的字节长度，再按字节序；
  乱序或重复键都算畸形
- 不允许不定长（indefinite-length）形式

示例：`0` → `00`，`24` → `1818`，`-1` → `20`，`"a"` → `6161`，
`[1, 2, 3]` → `83010203`，`{"b": 1, "aa": 2}` → `a261620162616102`，
`0.5` → `d93800`。更多逐字节样本见 `tests/vectors.py`。

## 实现说明

- 确定性：同一逻辑值在任何机器上编出的字节完全一致——整数与长度
  取最短宽度、浮点取最短无损宽度、字段表按键的规范序重排，不依赖
  字典插入顺序，总线上可以按字节做校验和与对齐。
- 健壮性：嵌套深度上限 `framing.MAX_DEPTH`，编解码两侧都生效，超深
  报 `DecodeError` / `EncodeError` 而不是爆栈；长度头只用来校验输入
  是否足够，绝不按声明长度预先分配，夸张的长度头会按截断报错。
- 流式解码：`StreamDecoder.feed` 接受任意切分的块（bytes / bytearray /
  memoryview），`finish` 收尾并返回对象；所有错误偏移都按整个流计，
  切法怎么变，结果都与一次性 `decode` 相同。
