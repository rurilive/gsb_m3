# segmerge

动态集合合并工具包的朴素基线，纯标准库，无外部依赖。

## 现状

segmerge/dynamic.py 里是 MergeTree，一棵树，节点用非负整数编号，每个节点
各挂一个权值小集合，父子关系由 parents 数组给出，负一表示根：

- node_count / root / children / local_weights：看节点数、取根、列直接子节点、取某点本地集合
- merged_values / size：自底向上把子树合出一只升序桶，报元素总个数
- count_of：某权值在合并集合里出现几次
- topk_sum：合并集合里前 k 大权值之和
- distinct_count：合并集合里不同权值的个数
- rank_of：某权值在合并集合里的排名（比它小的个数加一）
- kth_smallest：合并集合里第 k 小的权值
- merge_report：整棵树每个节点的总个数、不同个数、最小值与最大值
- naive_moves / clear_cache：累计逐个搬移次数与清空重算

这套做法是先把本节点自己的元素放进桶，再逐个取子节点合好的桶，把里面每
一个元素逐个追加进来，全部追加完整体排序一次；之后所有统计都在这只排序
桶上从头扫过，数出现次数、求前几大之和、数不同权值、算排名、取第几小。

## 问题

合并的代价与元素个数成正比。子树越大，往父节点里搬的元素越多，自底向上
走完整棵树就是元素总数与节点数相乘的量级，树退化成链时更是平方量级；合并
完还要整体排一次序，统计又每次都从头重扫，没有任何挂在权值上的加速结构。
既没有把两棵权值线段树递归合并成同一棵的能力，也没有小集合并入大集合的
启发式路子，缺一把尺子来印证合并结果到底对不对，暴露规模对照的入口也只
有朴素搬移次数这一个数字。
