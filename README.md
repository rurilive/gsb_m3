# wbuf

直接写通的内存存储，纯标准库，无外部依赖。写一条就落一条，读一条就看后端，
键与值都是普通对象。

## 现状

wbuf/store.py 提供 DictStore：

- DictStore()：建一个内存后端，内部就是一个字典
- put(key, value)：写一条并返回值，当场落到后端，键已存在则覆盖旧值
- get(key)：命中返回 (True, value)，未命中返回 (False, None)
- delete(key)：删一条并返回是否真的删掉
- keys()：全部键，按字典序
- dump()：全部键值对快照，键按字典序
- backend_writes()：后端被实际写入的次数，逐条累计
- len() / in：条目数与成员判断

每次写都直接落到后端，写次数与写请求一比一。

## 问题

每次写都直接打到后端，同一批里反复写同一个键也要一条条落，后端写次数
白白涨上去；写之间没有内存缓冲，短时间里的多次改动留不住，只能靠后端
兜着；没有刷盘策略，什么时候把攒下的改动一次性交出去无从控制；读只能
直奔后端，刚写进来还没落盘的最新值无处可查；也没有脏项口径，攒了多少
还没交出去的改动看不到；中途失败时已经交出去一半的批次怎样收场没有说法，
重放一遍还会不会重复写后端也不确定。
