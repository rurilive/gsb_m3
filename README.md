# exprx

规则引擎内嵌的表达式求值模块：词法 → 递归下降语法分析 → 求值，纯标准库。

## 语言语义

- 字面量：整数、小数；变量名：字母/下划线开头
- 运算符优先级（低 → 高）：`or` < `and` < 比较（`== != < <= > >=`）< `+ -` < `* / // %` < `^`（乘方，右结合）
- 一元负号：作用于整个乘方结果，`-2^2` 的值是 `-4`；`2^-3` 合法
- `and` / `or` 短路求值：左侧已能定值时右侧不求值，结果为布尔值
- `//` 与 `%` 是向下取整语义（与 Python 一致）：`-7 // 2 == -4`，`-7 % 2 == 1`
- `let x = e in body`：绑定仅在 body 内可见，退出后外层同名绑定不受影响，多次 evaluate 之间互不泄漏
- 除数为 0 时抛 `ZeroDivisionError`；引用未绑定变量抛 `NameError`

## 使用

```python
from exprx import Evaluator

ev = Evaluator()
ev.evaluate("let rate = 0.9 in amount * rate", {"amount": 80})
```

## 运行

```bash
python3 demo.py
```

## Known Issues

以下问题已修复（回归测试见 `tests/test_exprx.py`，运行 `python3 -m unittest discover tests`）：

- **负数幂符号反了（`-2^2` 算出 4）**：一元负号原先在语法分析的原子层处理，绑定优先级高于 `^`，被解析成 `(-2)^2`。修复：新增一元负号层级，优先级低于乘方、高于乘除，`-2^2` 现在等价 `-(2^2) == -4`，`2^-3` 仍合法。
- **`and`/`or` 不短路（`x != 0 and 10 / x > 2` 在 x=0 时抛 ZeroDivisionError）**：求值器原先先求值左右两支再组合布尔结果。修复：左侧已能定值时右侧不再求值，结果仍为布尔值。
- **负数 `//` / `%` 符号错误（`-7 % 2` 算出 -1）**：原先实现为 `int(left / right)`，是向零取整（且大数有浮点精度损失）。修复：改用 Python 原生的 `//` / `%`，向下取整语义，`-7 // 2 == -4`，`-7 % 2 == 1`。
- **`let` 绑定泄漏（`let x = 99 in ...` 后外层 x 被改）**：`let` 求值直接写共享绑定表且不恢复，污染外层作用域和后续 `evaluate` 调用。修复：进入 body 前保存同名旧绑定，退出时（含异常路径，try/finally）恢复或清除，绑定仅在 body 内可见。
