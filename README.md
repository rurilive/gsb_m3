# mincut

纯标准库的网络割工具雏形，无外部依赖。

## 现状

mincut/naive.py 提供几条朴素能力，全靠在边表上枚举边子集再走一遍连通性：

- min_cut、min_cut_value：求源汇最小割，枚举全部边子集，逐个丢掉后判断源点
  是否还走得到汇点，在割得开的子集里挑容量最小、割边最少、边编号序列字典序
  最小、源侧集合最小的一组，返回容量、源侧集合、割边编号
- is_cut：判断一组边是不是源汇割，丢掉这组边再走一遍深度优先连通性
- feasible_cut：判断给定容量下有没有不超过该容量的割
- global_min_cut_value：无向图全局最小割，枚举所有非空真子集当源侧取最小
- reachable：丢掉一组边后从源点出发能走到的点集
- CutTools：绑定一张图与一个口径，方法同上并累计枚举边子集的次数

所有结果都对，但每一问都要枚举边子集，子集数随边数指数上涨，边一多就跑不
动，也没有最大流分层增广、收缩合并这类做法，更缺多路互相印证的入口。

## 问题

边数一上去，枚举边子集的次数就指数爆炸；求最小割与判断给定容量下有没有割，
走的都是同一套枚举，重复劳动；想在最大流做法、收缩合并做法与枚举印证路之间
互相印证，也缺入口，规模对照更是读不到。

## 目标

在当前基础上补出最大流分层增广路、收缩合并路与独立枚举印证路，多路对同一批
数据逐项一致，并接上判断某组边是不是割、判断给定容量下有没有割两个独立能力，
暴露最大流增广次数与朴素枚举子集次数的规模对照，见任务描述。约束：

- 现有行为与 tests/test_naive.py 基线保持一致（基线一个字不改）
- 纯标准库
- 多条路结果逐项一致，各条路不许互相调用
