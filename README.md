# delayq

任务编排平台的延时队列，heapq 实现，时钟注入，纯标准库，无外部依赖。

## 模块说明

`delayq/queue.py` 提供延时队列 `DelayedQueue(clock=None)`：

- `add(task, delay, key=None)`：任务在 delay 秒后到期；key 相同的重复
  提交以最后一次为准，旧条目作废，不会被再次执行
- `pop_ready()`：只弹出已到期（due <= 当前时刻）的任务；同一时刻到期
  的任务按提交顺序出队；没有到期任务时返回 None
- `peek()`：距最近到期任务的等待秒数，消费端按它睡眠后再轮询；队列
  为空返回 None
- `len(queue)`：当前排队条目数（不含已作废条目）

`delayq/clock.py` 提供时钟抽象：`SystemClock` 为进程默认时钟，
`FakeClock` 支持 `advance()` / `jump_to()` 手动推进，供测试注入。

## Known Issues

以下线上反馈的四个现象均已修复，根因与修复说明如下（回归测试见
`tests/test_delayq.py`）：

1. **还没到点的任务被提前执行**
   根因：`pop_ready()` 弹出堆顶时从未检查到期时间与当前时刻的关系，
   只要队列非空就直接弹出队首任务。
   修复：弹堆前先比较堆顶 `due` 与 `clock.monotonic()`，未到期返回
   `None`，任务留在堆中等待。

2. **同一时刻到期的任务执行顺序飘忽**
   根因：堆元素为 `(due, delay, entry)`，`due` 并列时退化为比较
   `delay`，再并列时比较 `_Entry.__lt__`（同样只比 `due`），完全
   没有提交次序信息，heapq 对相等元素不保证稳定顺序，弹出次序随堆
   结构变化。
   修复：堆元素改为 `(due, seq, entry)`，`seq` 为单调递增的提交序号，
   同一时刻到期的任务严格按提交顺序（FIFO）出队。

3. **同一 key 重复提交的任务被执行两次**
   根因：`add()` 接收了 `key` 参数但从未使用，没有任何旧条目作废
   机制，重复提交的旧条目到期后照样被弹出执行。
   修复：维护 `key -> 最新条目` 映射，重复提交时将旧条目标记为
   `cancelled`（惰性删除）；`pop_ready()` / `peek()` 先清理堆顶的
   作废条目，作废条目不再被执行，也不再计入 `len(queue)`。

4. **消费进程 CPU 空转 / 一口睡过头**
   根因：`peek()` 返回的是堆顶任务的绝对到期时间戳，而非"距到期的
   剩余等待秒数"。消费端按该值睡眠会直接睡过截止时间很久（睡过
   头）；当时钟已越过该时间戳后，返回值变为零或负数，消费端立即
   重询形成忙轮询（CPU 空转）。
   修复：`peek()` 返回 `max(0.0, due - clock.monotonic())`，即剩余
   等待秒数且不为负；同时跳过已作废条目，避免按作废条目的时间
   睡眠。
