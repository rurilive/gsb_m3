# walog

元数据服务的预写日志与小型 KV 存储，单进程内嵌，纯标准库，无外部依赖。

## 模块

- `walog/wal.py`：`WriteAheadLog`——帧格式 `[2B 长度][JSON 载荷][4B CRC]`，append / replay / checkpoint，超过段大小自动切段（`wal-N.log`）
- `walog/store.py`：`KVStore`——内存视图 + 日志持久化，`recover()` 重放重建

## 运行

```bash
python3 demo.py
```

## 测试

```bash
python3 -m unittest discover -s tests -v
```

## Known Issues

以下问题已在本次修复，根因与修复方式如下（防回归测试见 `tests/`）：

1. **断电撕裂的半帧被当成有效记录恢复**
   根因：`_read_frames` 在 CRC 尾不足 4 字节时把校验值置 0，而 `if crc_val and ...` 的判断又跳过了校验，导致半帧直接通过；载荷被截断时也没有长度检查。
   修复：载荷或 CRC 读不满、CRC 校验失败一律停止重放；启动时还会截断活动段尾部的撕裂帧，避免后续追加写在垃圾之后永远读不回。

2. **超过 255 字节的字段重启后必丢**
   根因：写入侧用 2 字节小端存长度，读取侧 `_unpack_length` 却只取 `head[:1]` 一个字节，长度 ≥256 时被截断（如 300 变成 44），帧错位后 CRC 失败，整条记录被丢弃。
   修复：读取侧改为按 2 字节小端解析，与写入侧一致；并对超过 65535 字节的记录在写入时显式报错。

3. **恢复后旧值覆盖新值**
   根因：`_segments()` 按文件名字符串排序，`wal-10.log` 排在 `wal-2.log` 前面，段数超过 10 后重放顺序错乱，旧段后放、新值被旧值覆盖。
   修复：按段号数值排序后重放。

4. **已确认写入的记录断电后消失**
   根因：`append` 只写进 Python 文件缓冲，既不 `flush` 也不 `fsync`，进程退出或掉电时缓冲区数据未落盘。
   修复：`append` 每帧写入后立即 `flush` + `os.fsync`，返回即保证落盘。
