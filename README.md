# assignmatch

纯标准库的指派问题工具雏形，无外部依赖。

## 现状

assignmatch/naive.py 提供几条朴素能力，全靠枚举全部置换再逐个算总代价：

- min_cost_assignment、max_profit_assignment：求最小总代价与最大总收益的完美
  指派，逐个枚举零到工人数减一的全排列，算总代价后取极值，并列时按工人编号升
  序、每工人取最小任务编号取定
- assignment_cost：给定指派方案求总代价
- is_optimal：判断给定方案是不是最优，min 口径比最小代价，max 口径比最大收益
- best_partial_assignment：工人数与任务数不等或某些组合不可用时求最大匹配下的
  最优，枚举全部可行方案后先比接活人数再比总代价
- enumerate_permutations、permutation_count：全排列枚举与置换总数
- AssignTools：绑定一张矩阵，方法同上并累计枚举置换的次数

所有结果都对，但每一问都要过一遍全部置换，置换数随工人数阶乘上涨，人一多就跑
不动，也没有匈牙利增广、最小费用最大流这类做法，更缺多路互相印证的入口。

## 问题

工人数一上去，枚举置换的次数就阶乘爆炸；求最小代价与求最大收益、判断方案是否
最优、求最大匹配最优，走的都是同一套枚举，重复劳动；想在匈牙利增广做法、最小
费用最大流做法与枚举置换印证路之间互相印证，也缺入口，规模对照更是读不到。

## 目标

在当前基础上补出匈牙利增广路、最小费用最大流路与独立枚举印证路，多路对同一批
数据逐项一致，并接上最大匹配下的最优、给定方案求总代价与判断是否最优两个独立
能力，暴露匈牙利增广次数与朴素枚举置换次数的规模对照，见任务描述。约束：

- 现有行为与 tests/test_naive.py 基线保持一致（基线一个字不改）
- 纯标准库
- 多条路结果逐项一致，各条路不许互相调用

## 运行

```bash
python3 demo.py
python3 -m unittest discover -s tests -v
```
