# rangeq

一个只用 Python 标准库的小仓库，提供可变序列上的区间操作工具集。

## 现状

- 包名 `rangeq`，核心类 `Query`，位于 `rangeq/seq.py`。
- 内部只有一份平铺的 list，元素按构造给出的顺序保存，允许负数。
- `sum(left, right)` 对半开区间 `[left, right)` 内每个位置逐个累加，空区间返回 0。
- `add(left, right, delta)` 用循环对区间内每个位置逐个累加。
- `min_val` / `max_val` 逐个比较出区间最值，空区间抛 `EmptyRangeError`。
- `get(index)` / `set(index, value)` 直接读改数组里的单点，越界抛 `IndexOutOfRangeError`。
- `replay(values, operations)` 在副本上依次回放一串操作，返回末态与逐步返回值。
- 所有自定义异常继承自 `RangeqError`。

## 问题

每次区间求和、区间加或区间最值都要对区间内每个位置逐个重扫一遍，单点读改虽然
是常数量级，但改完之后没有任何聚合量可以复用。规模一上来，每次操作的代价就随
区间长度成正比上涨，序列里也没有任何分块或层级结构。

## 目标

把核心从平铺列表换成以分块（根号分治）为核心的序列工具集：把序列切成若干个
大小约为根号长度的块，每块维护元素之和与元素最值以及整块整体加的惰性标记；
整块命中的操作只改标记与块和，残缺块才逐元素处理，做到区间修改与区间查询均为
根号量级；支持单点查询与单点修改、区间求和、区间加、区间最值，以及把一个区间
整体复制或翻转；另用一条独立做法（差分数组配前缀和，或线段树）与分块路逐项
对照，对外暴露块数与被访问元素计数，把两条路的访问量差距量出来。改造后两条路
对同一批数据给出的事实必须逐项一致，原先那套朴素逐元素处理的路径保留下来做对照。
