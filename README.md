# quota

网关的多实例限流模块，纯标准库，无外部依赖。

## 现状

`quota/limiter.py` 提供 `FixedWindowLimiter`：按 key 做固定窗口计数，
窗口内放行到 `limit` 为止，跨窗口计数归零。窗口按注入时钟对齐切分，
`clock` 默认 `time.monotonic`，可构造传入假时钟。

接口：

- `allow(key="default")` — 有额度则放行并计数，否则拒绝
- `remaining(key="default")` — 当前窗口剩余额度

## 问题

计数只存在本进程内存里。服务从两台扩到六台后，每个实例各限各的，
同一个 key 的实际放行量随实例数一起放大，上游按总量给的配额被整体击穿。

## 目标

见任务描述。约束：

- `tests/test_limiter.py` 是行为基线，一个字不改
- 时钟与共享存储都要可注入，测试不做真实 sleep
- 纯标准库

## 运行

```bash
python3 demo.py                          # 限流现状演示
python3 -m unittest discover -s tests -v # 行为基线测试
```

## 实现说明

- 额度记账：共享存储按 (key, 窗口起点) 记已发出额度，`claim`/`release` 原子执行；实例本地只缓存预领余量，不参与全局计数。
- 预领粒度：`batch` 控制每次向存储认领的量——大则省远程往返，小则少闲置；崩溃实例已花未报的零头会随租约一并回收，批量越大这笔误差越大。
- 回收：实例 `close()` 或本地时钟跨窗时归还未花额度；崩溃实例的租约（`lease_ttl`）到期后，由其他实例下次认领时顺带回收。
- 窗口对齐：窗口边界只按存储侧时钟切分，实例本地时钟仅决定何时回存储对账，各机时钟差几秒不会把窗口划岔。
- 降级口径：存储故障时默认 fail-closed 拒绝，`key_on_error={"vip": "open"}` 可按 key 配成 fail-open 放行，降级期间放行不记账。
