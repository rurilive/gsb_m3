# hllbox

基数估计小库，纯标准库，无外部依赖。调用方喂进一串元素，想知道其中
不同元素大概有多少，要求内存只随配置的桶数固定，不随元素种类数增长。

## 现状

- `hllbox/naive.py`：`ExactSet`，一套全量精确去重。`add(key)` 记入一个
  元素（非空字符串，重复加入不改变个数），`add_many(keys)` 逐个加入，
  `count()` 给出不同元素的精确个数，`contains(key)` 判断是否记过，
  `union(other)` 把另一个集合并进来，`reset()` 回到初态。

元素原样存在一个集合里，谁也不丢。计数精确，但集合会随不同元素的
个数一直涨，元素基数大时内存无界；没有固定大小的寄存器草图，没有
估计值，没有误差口径与偏差修正，不能把两个结构并起来估并集，更没有
稀疏与稠密两套表示。

## 问题

全量集合在元素基数大时内存随种类数无界增长，装不下也扛不住；只有
精确计数，没有固定内存的估计与误差上界；没有按桶分摊、没有稀疏与
稠密表示，小基数也要占满一整块桶；两个结构不能合并取并集。
