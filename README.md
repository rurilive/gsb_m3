# quota

网关的多实例限流模块，纯标准库，无外部依赖。

## 现状

`quota/limiter.py` 提供 `FixedWindowLimiter`：按 key 做固定窗口计数，
窗口内放行到 `limit` 为止，跨窗口计数归零。窗口按注入时钟对齐切分，
`clock` 默认 `time.monotonic`，可构造传入假时钟。

接口：

- `allow(key="default")` — 有额度则放行并计数，否则拒绝
- `remaining(key="default")` — 当前窗口剩余额度

## 问题

计数只存在本进程内存里。服务从两台扩到六台后，每个实例各限各的，
同一个 key 的实际放行量随实例数一起放大，上游按总量给的配额被整体击穿。

## 目标

见任务描述。约束：

- `tests/test_limiter.py` 是行为基线，一个字不改
- 时钟与共享存储都要可注入，测试不做真实 sleep
- 纯标准库

## 运行

```bash
python3 demo.py                          # 限流现状演示
python3 -m unittest discover -s tests -v # 行为基线测试
```

## 实现说明

- 额度记账：共享存储按 `(key, 窗口)` 原子记录窗口累计已领 `taken`，预领即从余量里扣，六台合起来不超过 `limit`。
- 预领粒度：实例本地按批领、批内不再远程往返；整批花完批量翻倍，换窗口/归还时手里有剩余则减半，自适应贴合用量。
- 回收：每批额度挂在实例租约上（`lease_ttl`），活着就续租并上报剩余持有量；掉线后 TTL 到期，存储只回收真正没花完的部分；`shutdown()` 可提前主动归还。
- 窗口对齐：窗口边界完全由存储时钟切，实例用存储回包校掉本地时钟偏差，机器差两秒也不会在边界两头各放一批；旧窗口剩余额度跨窗口作废。
- 降级口径：存储抖动导致新一批领不出时，`fail_policy` 按 key 配 `fail_open`（放行保可用）或 `fail_closed`（拒绝保配额，默认），支持字符串、dict、callable；已领到手的额度抖动期间照花。
