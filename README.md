# eventlog

事件溯源存储，纯标准库，无外部依赖。调用方把领域事件追加进来，按流
读回、打快照、重放投影、订阅新事件。

## 现状

`eventlog/log.py` 提供 `EventLog`，一个最朴素的只追加全局事件列表：

- `append(event)`：把一个事件排到全局列表末尾，返回它在全局序列里的
  下标（从 0 起）
- `read()`：按追加顺序读回全部事件，返回列表副本
- `__len__()`：当前事件条数
- `__iter__()`：按追加顺序遍历事件

事件按对象原样存放，不打包、不带版本、不做任何并发检查。所有事件挤在
一条全局序列里，没有流的区分。

## 问题

只有一条全局事件序列：所有业务的事件混在一起，没法按业务实体（流）
分开读取，也就没法让每个流各自维护版本。追加没有版本校验，两个写入者
同时追加只会盲目排到末尾，谁覆盖了谁无从发现。没有快照，状态只能每次
从头重放，事件一多就慢。没有投影，从事件归约出状态这件事要调用方自己
从头写。没有订阅，新事件进来没有推送，只有主动轮询。这些都见任务描述。
