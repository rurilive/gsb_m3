# delayq

任务编排平台的延时队列，heapq 实现，时钟注入，纯标准库，无外部依赖。

## 模块说明

`delayq/queue.py` 提供延时队列 `DelayedQueue(clock=None)`：

- `add(task, delay, key=None)`：任务在 delay 秒后到期；key 相同的重复
  提交以最后一次为准，旧条目作废，不会被再次执行
- `pop_ready()`：只弹出已到期（due <= 当前时刻）的任务；同一时刻到期
  的任务按提交顺序出队；没有到期任务时返回 None
- `peek()`：距最近到期任务的等待秒数，消费端按它睡眠后再轮询；队列
  为空返回 None
- `len(q)`：当前排队条目数

`delayq/clock.py` 提供时钟抽象：`SystemClock` 为进程默认时钟，
`FakeClock` 支持 `advance()` / `jump_to()` 手动推进，供测试注入。

## 运行

```bash
python3 demo.py
```

## Known Issues

以下线上现象均已修复，根因与修复方式如下（防回归测试见 `tests/`）：

1. **还没到点的任务被提前执行**
   根因：`pop_ready()` 弹出堆顶时未校验到期时间，不管 `due` 是否
   大于当前时刻都直接弹出返回。
   修复：弹出前比较堆顶 `due` 与 `clock.monotonic()`，未到期返回 None。

2. **同一时刻到期的任务执行顺序飘忽**
   根因：堆元素为 `(due, delay, entry)`，且 `_Entry.__lt__` 只比较
   `due`；同时刻到期的条目比较结果相等，heapq 不保证稳定序，出队
   顺序取决于堆的内部形态，随提交历史变化。
   修复：堆元素改为 `(due, seq, entry)`，`seq` 取自单调递增计数器，
   同时刻到期的任务严格按提交顺序（FIFO）出队。

3. **同 key 重复提交的任务被执行两次**
   根因：`add()` 接收了 `key` 参数但从未使用，旧条目没有任何作废
   机制，到期后照样被弹出执行。
   修复：维护 key → 最新条目的映射，重复提交时给旧条目打
   `cancelled` 标记（懒删除），`pop_ready()`/`peek()` 先丢弃堆顶
   已作废条目；`len()` 只统计有效条目。

4. **消费端 CPU 空转 / 睡过头错过整批任务**
   根因：`peek()` 返回的是堆顶条目的绝对到期时刻，而非距当前时刻
   的剩余等待秒数。消费端拿它当 sleep 时长会睡过头（起点非零时
   多睡整个起始偏移）；而任务被提前弹空后 `peek()` 返回 None，
   消费端退化成无等待忙轮询，CPU 打满。
   修复：`peek()` 返回 `max(0.0, due - clock.monotonic())`，即真实
   剩余等待秒数，并先跳过已作废条目。
