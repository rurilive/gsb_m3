# exprx

规则引擎内嵌的表达式求值模块：词法 → 递归下降语法分析 → 求值，纯标准库。

## 语言语义

- 字面量：整数、小数；变量名：字母/下划线开头
- 运算符优先级（低 → 高）：`or` < `and` < 比较（`== != < <= > >=`）< `+ -` < `* / // %` < `^`（乘方，右结合）
- 一元负号：作用于整个乘方结果，`-2^2` 的值是 `-4`；`2^-3` 合法
- `and` / `or` 短路求值：左侧已能定值时右侧不求值，结果为布尔值
- `//` 与 `%` 是向下取整语义（与 Python 一致）：`-7 // 2 == -4`，`-7 % 2 == 1`
- `let x = e in body`：绑定仅在 body 内可见，退出后外层同名绑定不受影响，多次 evaluate 之间互不泄漏
- 除数为 0 时抛 `ZeroDivisionError`；引用未绑定变量抛 `NameError`

## 使用

```python
from exprx import Evaluator

ev = Evaluator()
ev.evaluate("let rate = 0.9 in amount * rate", {"amount": 80})
```

## 运行

```bash
python3 demo.py
```

## Known Issues

以下问题均已修复（修复与防回归测试见 `tests/test_exprx.py`）：

1. **`-2^2` 错误返回 `4`（运算符优先级表缺陷）**
   根因：一元负号原来在 `_atom` 层处理，优先级比乘方 `^` 还高，
   `-2^2` 被当成 `(-2)^2` 解析。修复后在乘除与乘方之间新增独立的一元负号层，
   解析为 `-(2^2)`，结果为 `-4`；同时 `2^-3` 仍合法（乘方右支走一元层）。

2. **`x != 0 and 10 / x > 2` 在 `x = 0` 时抛 `ZeroDivisionError`（短路失效）**
   根因：`and` / `or` 节点先无条件递归求值左右两支，再交给 Python 的 `and`/`or`
   做布尔运算——此时右支 `10 / x` 已经除零。修复为左支先求值并按真值决定是否求值右支，
   左支已能定值时右支完全不求值，返回值仍为布尔值。

3. **`-7 % 2` 错误返回 `-1`、`-7 // 2` 错误返回 `-3`（取整方向缺陷）**
   根因：两个运算都基于 `int(left / right)` 实现，走的是向零截断，
   与文档承诺的向下取整（floor）不符。修复为直接采用 Python 的 `//` 与 `%`，
   二者满足恒等式 `a == (a // b) * b + a % b`，余数与除数同号：
   `-7 // 2 == -4`、`-7 % 2 == 1`。

4. **`let x = 99 in ...` 污染外层同名变量（作用域缺陷）**
   根因：求值 `let` 时直接把新值写入求值器唯一的绑定表且退出时不恢复，
   导致 body 结束后绑定残留，嵌套 `let` 的外层同名绑定以及后续规则（下一次
   `evaluate`）都被污染。修复为进入 `let` 前保存旧绑定（含“未绑定”状态），
   body 求值后（含异常路径）在 `finally` 中恢复或删除，绑定仅在 body 内可见。
   注：通过 `variables` 显式传入的外部绑定仍按文档挂在求值器实例上跨调用复用，
   不受影响。
