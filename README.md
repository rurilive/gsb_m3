# idemkey

支付链路的幂等键存储：按幂等键记住已处理请求的结果，同一个键再提交时
回放上次的结果，避免重复扣款。纯标准库，无外部依赖。

## 模块说明

`idemkey/store.py` 提供 `IdempotencyStore(ttl=None, clock=time.monotonic,
path=None)`：

- `begin(key)`：提交前问这个键要不要干活。返回 `True` 表示该由本次请求
  处理；返回 `False` 表示这个键已经处理过，调用方改用 `get(key)` 回放结果。
  键被占上但一直没 `finish`（上次处理中途失败）时视为可重试，返回 `True`
  让本次请求接手
- `finish(key, result)`：把处理结果记到键上，这个键之后就算已处理
- `get(key)`：取这个键已记下的结果，没有就返回 `None`
- `ttl`：记录存活秒数，`None` 表示永不过期
- `clock`：时间读取统一走它，便于测试注入
- `path`：记录落盘的文件路径，`None` 表示只放内存

记录字段：`result` 保存结果，`created_at` 是键被占上的时刻，`finished_at`
是收尾时刻。过期从收尾时刻起算 ttl，没收尾的记录从占键时刻起算。内部一把
锁保护，磁盘读写也在锁内完成。

## 运行

```bash
python3 demo.py                          # 现象演示

```

## Known Issues

以下四类问题已修复，根因和修法记录在此，防回归测试见
`tests/test_regressions.py`：

1. **只差大小写的单号被并成一笔**：`_normalize` 把键统一转小写，
   `Order-7001` 和 `order-7001` 被当成同一个键，后一单直接拿到前一单的
   回执，造成重复扣款。修法：规范化只去首尾空白，不再改大小写，大小写
   不同的键是两笔独立的单。
2. **重启后键还在、结果没了**：`finish` 写完结果没有落盘，只有 `begin`
   会 `_save`，重启后从磁盘读回的是占键时的空记录——键在、结果为
   `None`，重发被判成重复又取不到结果。修法：`finish` 写结果后立即落盘；
   过期清理发生时也同步落盘，避免磁盘上残留已过期记录。
3. **处理中途失败后键被卡死**：`begin` 占键后只要记录存在就一律返回
   `False`，上次请求中途失败没来得及 `finish`，这个键就永远占着，重发
   只能拿到 `None`。修法：`begin` 只对已收尾（`finished_at` 非空）的记录
   返回 `False`；占键未收尾的记录视为上次处理失败，允许本次请求重新
   接手。
4. **耗时请求的结果刚写完就被清掉**：过期判断按 `created_at`（占键时刻）
   起算，处理耗时超过 ttl 的单子，`finish` 时记录已经过期，下一次
   `begin`/`get` 就被清掉。修法：已收尾的记录按 `finished_at`（收尾时刻）
   起算 ttl，没收尾的仍按占键时刻起算。
