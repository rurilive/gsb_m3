# flownet

纯标准库的有向容量网络最大流与最小割工具雏形，无外部依赖。

## 现状

flownet/naive.py 提供几条朴素能力，求最大流靠单路增广，求最小割靠枚举边子集：

- max_flow：反复在残量网络上做一次广度搜索，找到一条到汇点的增广路就沿路推
  流，推完重新搜下一条，直到找不到为止；结果里带增广路条数与各边最终流量
- min_cut、min_cut_value：求源汇最小割，枚举全部边子集，逐个丢掉后判断源点
  是否还走得到汇点，在割得开的子集里挑容量最小、割边最少、割边编号序列字典
  序最小、源侧集合最小的一组，返回容量、源侧集合、割边编号
- is_cut：判断一组边是不是源汇割，丢掉这组边再走一遍连通性
- feasible_cut：判断给定容量下有没有不超过该容量的割
- edge_subset_count：朴素枚举边子集时要过一遍的子集总数
- FlowNetwork：一张有向容量网络，暴露单路增广、流量清零与残量可达性
- FlowTools：绑定一张图与源汇，方法同上并累计单路增广次数与枚举边子集次数

所有结果都对，但每一轮增广都要重搜整张残量网络，增广次数与路径长度同阶；最小
割那一问枚举边子集，子集数随边数指数上涨，边一多就跑不动，也没有分层图多路增
广、当前弧优化与残量图直接构造割这类做法，更缺多路互相印证的入口。

## 问题

单路增广在容量大的图上要反复重搜，轮数惊人；求最小割与判断给定容量下有没有割
走的都是同一套指数枚举，重复劳动；想在新老两条路径、以及容量下界可行流、最小
费用最大流、最大流最小割对偶断言之间互相印证，也缺入口，规模对照更是读不到。

## 目标

在当前基础上补出以分层图多路增广与当前弧优化为主路径的最大流核心，补出由最大
流残量图直接构造的最小割，让它与独立枚举口径逐项对齐，并接上容量下界可行流、
最小费用最大流与最大流最小割对偶断言等独立能力，暴露多路增广轮数与单路增广次
数的规模对照，见任务描述。约束：

- 现有行为与 tests/test_naive.py 基线保持一致（基线一个字不改）
- 纯标准库
- 多条路结果逐项一致，各条路不许互相调用

## 运行

```bash
python3 demo.py
python3 -m unittest discover -s tests -v
```
