# walog

一个纯标准库的预写日志，无外部依赖。数据库、键值存储这类系统在真正改动数据
之前，先把一条条变更按次序记到日志里，walog 就是干这件事的那一层。

## 现状

- `walog/log.py`：`Log` 把条目按追加次序放进一个内存列表。
  - `append(payload)`：在末尾落一条负载，返回它在列表里的位置（从 0 开始）
  - `read(pos)`：按位置读回一条负载，位置越界即报错
  - `__len__()`：当前条目数
  - `reset()`：清空全部条目
- `walog/errors.py`：`WalogError` 基类，以及 `InvalidLsn`、`TruncateError`、
  `CorruptEntry` 三种具体错误。

现有实现只是一个内存追加列表：条目没有序号，也不知道自己写到了哪儿；没有
检查点，重启后只能从头再放一遍；没有截断，已经没必要留的旧条目丢不掉；没有
校验和，一条被写坏的日志读出来和好的一样；更没有重放，日志记下了也无从重建
状态机。

## 问题

没有序号，同一条变更在日志里的位置说不清，重放时也无从对齐；没有检查点，
每次都从头重放，日志越长恢复越慢；没有截断，旧条目只增不减，空间收不回来，
而截断一个未来的位置又该怎么拒绝也没个准；没有校验和，一条被写坏的副本会被
当成好条目重放，状态机就此被污染；没有崩溃恢复的对拍，谁也说不清从检查点加
其后日志恢复出来的状态是否与崩溃前一致。

## 目标

见任务描述。约束：

- 现有行为与 `tests/test_log.py` 基线一致（基线一个字不改）
- 纯标准库，Python 3.10+
- 序号非法与截断到未来的位置一律 fail fast
- 同一份日志重放两次必须得到同样的状态
