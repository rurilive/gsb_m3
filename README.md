# cascadectl

单层 LRU 缓存，纯标准库，无外部依赖。放进去、取出来、满了挤掉最久没用的
那条，键与值都是一般对象，没有过期时间，也没有上下两级。

## 现状

cascadectl/cache.py 提供 LRUCache：

- LRUCache(capacity)：按条目数上限构造，容量小于一在构造处拒绝
- get(key)：命中返回 (True, value)，未命中返回 (False, None)
- put(key, value)：写入并返回值，已存在的键覆盖值并提出到最新
- evict()：主动挤掉最久未使用的条目并返回其键，空缓存返回 None
- peek(key)：只看不更新使用次序，键不存在返回 None
- keys()：全部键，按最近使用次序从早到晚
- stats()：容量、条目数、命中、未命中与淘汰数
- len() / in：条目数与成员判断

淘汰挑最久未使用的条目，被淘汰的条目直接消失。

## 问题

只有一层，热数据与温数据挤在同一个容量里，热条目的位置白白被温条目占着；
淘汰掉的条目直接丢弃，没有下级可降级，也没法把真正丢弃推迟到更后面；
条目进了缓存就永远有效，没有存活时间，陈旧数据只能靠覆盖写清掉；没有
回写队列，脏条目淘汰时无处安放写动作，失败也无从重试；命中口径只有一层，
分不清哪些命中来自快的那层、哪些来自慢的那层，提升与降级各发生了几回也
看不到。
