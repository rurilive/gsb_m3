# exprx

规则引擎内嵌的表达式求值模块：词法 → 递归下降语法分析 → 求值，纯标准库。

## 语言语义

- 字面量：整数、小数；变量名：字母/下划线开头
- 运算符优先级（低 → 高）：`or` < `and` < 比较（`== != < <= > >=`）< `+ -` < `* / // %` < `^`（乘方，右结合）
- 一元负号：作用于整个乘方结果，`-2^2` 的值是 `-4`；`2^-3` 合法
- `and` / `or` 短路求值：左侧已能定值时右侧不求值，结果为布尔值
- `//` 与 `%` 是向下取整语义（与 Python 一致）：`-7 // 2 == -4`，`-7 % 2 == 1`
- `let x = e in body`：绑定仅在 body 内可见，退出后外层同名绑定不受影响，多次 evaluate 之间互不泄漏
- 除数为 0 时抛 `ZeroDivisionError`；引用未绑定变量抛 `NameError`

## 使用

```python
from exprx import Evaluator

ev = Evaluator()
ev.evaluate("let rate = 0.9 in amount * rate", {"amount": 80})
```

## 运行

```bash
python3 demo.py
```

## Known Issues

以下缺陷已修复（2026-09-20），根因与修复说明如下：

- **负数幂符号反了**：`-2^2` 曾得 `4`。根因：一元负号在原子层处理，先于乘方结合，被解析成 `(-2)^2`。修复：一元负号下沉到乘方之下（优先级表新增 unary 层），`-2^2 == -(2^2) == -4`，`2^-3` 仍合法。
- **`and`/`or` 不短路**：`x != 0 and 10 / x > 2` 在 `x = 0` 时抛 `ZeroDivisionError`。根因：求值器先算完左右两支再取布尔，右侧必被求值。修复：改为短路求值，左侧已能定值时右侧不执行。
- **负数取模/整除方向错误**：`-7 % 2` 曾得 `-1`，`-7 // 2` 曾得 `-3`。根因：用 `int(left / right)` 实现，是向零取整而非向下取整，余数符号跟着错了。修复：直接使用 Python 的 `//` 与 `%`（地板语义），`-7 // 2 == -4`，`-7 % 2 == 1`。
- **`let` 绑定泄漏**：`let x = 99 in ...` 求值后外层及后续同名规则被污染。根因：绑定直接写入求值器共享环境且从不恢复。修复：进入 body 前保存外层同名绑定，退出时恢复（无外层绑定则删除），多次 `evaluate` 之间互不泄漏。
